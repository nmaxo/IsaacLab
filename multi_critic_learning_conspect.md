## 1. Основная Идея и Мотивация

### 1.1 Проблема

В задачах одновременного обучения ходьбе и манипуляциям возникает **конфликт целей**:

- **Для эффективной ходьбы:** робот должен держать корпус горизонтально и стабильно
- **Для работы манипулятором:** часто требуется наклонять корпус, чтобы дотянуться до цели

### 1.2 Традиционный Подход (Single-Critic)

Один критик оценивает общее качество действий, суммируя все награды в одно число:

$$V(s_t) = \text{evaluate}(r_{\text{loco}} + r_{\text{mani}} + r_{\text{contact}})$$

**Проблема:** Это приводит к тому, что одна задача "подавляет" другую, особенно если награды имеют разный масштаб (например, $r_{\text{loco}} \sim \pm 100$, а $r_{\text{mani}} \sim \pm 1$).

### 1.3 Решение: Multi-Critic Learning

**Ключевая идея:** Разделение сигналов наград на независимые группы, каждая со своим критиком.

Вместо смешивания всех наград в одну кучу:
- Создаются три независимые нейросети-критика
- Каждая оценивает свою специфическую задачу
- Их оценки агрегируются на финальном этапе

## 2. Архитектура Системы

### 2.1 Три Независимых Критика

Система использует **три полностью отдельные нейросети (MLP)**, каждая со своими весами:

```
┌─────────────────────────────────────────────────────────────┐
│                     ACTOR (Policy π_θ)                       │
│                    [Одна нейросеть]                          │
│                                                               │
│  Input: s_t  →  Hidden Layers  →  Output: Action a_t        │
└─────────────────────────────────────────────────────────────┘
                              ↓
                    Робот выполняет a_t
                              ↓
            Среда возвращает: s_{t+1}, награды
                              ↓
        ┌─────────────────────┬─────────────────────┐
        ↓                     ↓                     ↓
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│ CRITIC 1      │     │ CRITIC 2      │     │ CRITIC 3      │
│ (Locomotion)  │     │ (Manipulation)│     │ (Contact)     │
│               │     │               │     │               │
│ φ_loco        │     │ φ_mani        │     │ φ_cs          │
│               │     │               │     │               │
│ Input: s_t    │     │ Input: s_t    │     │ Input: s_t    │
│ Output: V^loco│     │ Output: V^mani│     │ Output: V^cs  │
└───────────────┘     └───────────────┘     └───────────────┘
```

#### **Критик 1: Locomotion Critic ($\phi_{\text{loco}}$)**

**Цель:** Контроль движения базы робота

**Награды:**
- Линейная скорость базы $v_{xy}$ (насколько быстро движемся)
- Угловая скорость базы $\omega_z$ (правильность поворотов)
- Ориентация базы (стабильность, избегание заваливания)

**Функция награды:**
$$r_{\text{loco}} = w_1 \cdot r_{v_{xy}} + w_2 \cdot r_{\omega_z} + w_3 \cdot r_{\text{orientation}}$$

#### **Критик 2: Manipulation Critic ($\phi_{\text{mani}}$)**

**Цель:** Точное управление энд-эффектором

**Награды:**
- Позиция энд-эффектора (расстояние до цели)
- Ориентация энд-эффектора (правильный угол поворота хвата)

**Функция награды:**
$$r_{\text{mani}} = w_4 \cdot r_{\text{pos}} + w_5 \cdot r_{\text{orient}}$$

**Важно:** Этому критику всё равно, стоит робот или идет — главное, где находится рука относительно цели.

#### **Критик 3: Contact Schedule Critic ($\phi_{\text{cs}}$)**

**Цель:** Правильный ритм ходьбы (gait pattern)

**Награды:**
- Силы реакции опоры (наступает ли нога, когда должна)
- Скорость ног в полете (избегание волочения)

**Зачем нужен ритм шагов?**

Без этого критика робот может научиться странным, неестественным походкам:
- Прыгать на двух ногах
- Волочить ноги по земе
- Использовать нестабильные паттерны

"Расписание контактов" задает жесткий ритм (обычно синусоидальный сигнал), которому робот обязан следовать. Это критично для:
- **Стабильности** в реальном мире
- **Sim-to-real transfer**
- **Предсказуемости** поведения

### 2.2 Структура Критика (Детали)

#### Вход (Input)

**Только текущее состояние** $s_t$, включающее:

```python
s_t = {
    # Проприоцептивные данные (онбордные сенсоры)
    "joint_positions": θ,          # Углы суставов
    "joint_velocities": θ̇,         # Скорости суставов
    
    # Команды пользователя
    "velocity_command": v_cmd,     # Целевая скорость базы
    "ee_target": x_target,         # Целевая позиция руки
    
    # Привилегированная информация (только на обучении!)
    "height_map": scan_dots,       # Карта высот местности
    "base_velocity": v_base,       # Точные скорости (недоступно на роботе)
    "external_forces": F_ext,      # Внешние воздействия
    "friction_coefficient": μ      # Трение поверхности
}
```

> **Примечание:** Привилегированная информация используется только на этапе обучения Teacher Policy. При переносе на реального робота (Student Policy) она недоступна.

#### Выход (Output)

Одно скалярное значение — **предсказанная ценность состояния**:

$$V_{\phi_k}(s_t) \in \mathbb{R}$$

Это число отвечает на вопрос: *"Сколько суммарной награды (по моей специфической задаче) я ожидаю получить в будущем из этого состояния?"*

#### Важно!

**Предыдущее состояние** $s_{t-1}$ и **награда** $r_t$ **НЕ подаются на вход** нейросети критика!

Они используются только снаружи, в формуле для расчета ошибки (Loss), чтобы обучать сеть.

## 3. Процесс Обучения

### 3.1 Обучение Критиков: Temporal Difference Learning

Каждый критик учится **независимо** через метод bootstrapping (самообучение).

#### Концепция: "Барон Мюнхгаузен"

Критик пытается предсказать своё же собственное предсказание, но "немного более точное", используя реальные данные как якорь.

#### Алгоритм обучения (5 шагов):

##### Шаг 1: Предсказание "До" (Initial Guess)

Робот находится в состоянии $s_t$.

Критик оценивает его:

$$V_{\phi}(s_t) = 10 \quad \text{(условно)}$$

Это просто догадка нейросети.

##### Шаг 2: Реальность (Reality Check)

Робот делает шаг:
- Выполняет действие $a_t$
- Получает **реальную награду** $r_t = 1$ (конкретное число из среды)
- Переходит в новое состояние $s_{t+1}$

##### Шаг 3: Предсказание "После" (Lookahead)

Критик оценивает **новое** состояние:

$$V_{\phi}(s_{t+1}) = 9.5$$

##### Шаг 4: Конструирование "Правильного Ответа" (Target)

Теперь мы можем составить более точную оценку для первого состояния $s_t$.

**Уравнение Беллмана:**

$$V_{\text{target}} = r_t + \gamma V_{\phi}(s_{t+1})$$

Где $\gamma = 0.99$ — коэффициент дисконтирования (будущее ценится чуть меньше настоящего).

**Пример:**

$$V_{\text{target}} = 1 + 0.99 \cdot 9.5 = 10.405$$

**Интерпретация:** 
- Мы **точно знаем**, что получили $1$ очко сейчас (реальный факт)
- Мы **доверяем критику**, что из $s_{t+1}$ можно получить еще $9.5$ очков
- Значит, "истинная" ценность $s_t$ должна была быть $10.405$

##### Шаг 5: Обновление Весов (Gradient Descent)

**Функция потерь (MSE Loss):**

$$\mathcal{L}(\phi) = (V_{\phi}(s_t) - V_{\text{target}})^2$$

**В нашем примере:**

$$\mathcal{L}(\phi) = (10 - 10.405)^2 = 0.164$$

**Градиент:**

$$\nabla_{\phi} \mathcal{L} = 2 \cdot (V_{\phi}(s_t) - V_{\text{target}}) \cdot \nabla_{\phi} V_{\phi}(s_t)$$

Критик ошибся на $-0.405$. Градиент обновляет веса так, чтобы в следующий раз предсказание было ближе к $10.405$.

#### Почему это работает?

Кажется странным: мы используем предсказание критика $(9.5)$, чтобы обучить того же самого критика. Не бред ли это?

**Нет!** Потому что в формуле $V_{\text{target}}$ есть слагаемое $r_t$ — это **"якорь реальности"**.

На каждом шаге мы подмешиваем кусочек реальной информации:

```
Итерация 1: V(s_t) ← r_t + γ·V(s_{t+1})  [r_t реальная]
Итерация 2: V(s_t) ← r_t + γ·V(s_{t+1})  [V(s_{t+1}) чуть точнее]
...
Итерация N: V(s_t) ← точное предсказание
```

Постепенно (за миллионы шагов) эта реальная информация **распространяется "назад во времени"**, и предсказания критика становятся точными.

Это называется **Temporal Difference Learning (TD-Learning)**.

### 3.2 Вычисление Преимущества (Advantage Estimation)

Для каждого критика $k$ вычисляется **GAE (Generalized Advantage Estimation)**.

#### Что такое Advantage?

**Advantage** $\hat{A}_t$ отвечает на вопрос:

> *"Насколько действие $a_t$ **лучше среднего** действия в ситуации $s_t$?"*

- $\hat{A}_t > 0$ → действие **лучше** ожидаемого (хвалим)
- $\hat{A}_t < 0$ → действие **хуже** ожидаемого (наказываем)
- $\hat{A}_t = 0$ → действие ровно среднее (нейтрально)

#### Алгоритм GAE

##### 1. TD-ошибка (Temporal Difference Error)

$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

**Интерпретация:**
- Если $\delta_t > 0$ → "сюрприз со знаком плюс" (получили больше, чем ожидали)
- Если $\delta_t < 0$ → "разочарование" (получили меньше)

##### 2. Расчет Advantage с затуханием

$$\hat{A}_t = \sum_{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}$$

Развернуто:

$$\hat{A}_t = \delta_t + (\gamma \lambda) \delta_{t+1} + (\gamma \lambda)^2 \delta_{t+2} + \dots$$

Где:
- $\gamma = 0.99$ — дисконтирование по времени
- $\lambda = 0.95$ — параметр GAE (обычно, баланс между bias и variance)

**Эффект:** Мы смотрим не только на текущий шаг, но и на несколько шагов вперед, с затуханием.

#### Независимость критиков

**Критически важно:** Каждый критик считает свой GAE **независимо**!

Например, после одного и того же действия $a_t$:

```
Критик "Locomotion":
  r^loco = +2.5  (отличный шаг!)
  δ^loco = +1.2
  Â^loco = +3.4  ✓ Положительное преимущество

Критик "Manipulation":
  r^mani = -0.8  (рука дернулась)
  δ^mani = -0.3
  Â^mani = -1.1  ✗ Отрицательное преимущество

Критик "Contact":
  r^contact = +0.1  (ритм в норме)
  δ^contact = +0.05
  Â^contact = +0.2  ✓ Положительное преимущество
```

Эти три числа потом будут агрегированы.

### 3.3 Агрегация Преимуществ (Ключевое Отличие!)

#### Формула агрегации

$$\hat{A}^{\text{tot}}_t = \sum_{k=1}^{3} \frac{\hat{A}^k_t - \mu(\hat{A}^k)}{\sigma(\hat{A}^k) + \epsilon}$$

Где:
- $\hat{A}^k_t$ — сырое преимущество от $k$-го критика
- $\mu(\hat{A}^k)$ — **среднее** преимуществ критика $k$ по батчу (batch statistics)
- $\sigma(\hat{A}^k)$ — **стандартное отклонение** преимуществ по батчу
- $\epsilon = 10^{-8}$ — малое число для численной стабильности

#### Зачем нормализация?

**Проблема без нормализации:**

Если награды имеют разный масштаб:
- $\hat{A}^{\text{loco}} \in [-50, +50]$ (большие значения)
- $\hat{A}^{\text{mani}} \in [-1, +1]$ (маленькие значения)

То при простом сложении:

$$\hat{A}^{\text{tot}} = 45 + 0.5 + 0.2 = 45.7$$

Сигнал от манипуляции ($0.5$) **полностью теряется** на фоне локомоции ($45$)!

**Решение — нормализация:**

После деления на $\sigma$:
- $\hat{A}^{\text{loco}}_{\text{norm}} \in [-2, +2]$ (стандартизировано)
- $\hat{A}^{\text{mani}}_{\text{norm}} \in [-2, +2]$ (стандартизировано)

Теперь оба сигнала имеют **одинаковый вес**:

$$\hat{A}^{\text{tot}} = 1.2 + (-0.8) + 0.1 = 0.5$$

#### Важное уточнение: $\alpha_k$ (весовые коэффициенты)

**Цитата из статьи:**

> "Unlike previous works [7, 27], our method avoids weighted averaging during advantage estimation, which further reduces the number of hyperparameters that require tuning."

**Перевод:** В этой работе авторы **НЕ используют** весовые коэффициенты $\alpha_k$!

Вместо взвешенной суммы:

$$\hat{A}^{\text{tot}} = \alpha_1 \cdot \hat{A}^1_{\text{norm}} + \alpha_2 \cdot \hat{A}^2_{\text{norm}} + \alpha_3 \cdot \hat{A}^3_{\text{norm}}$$

Они просто складывают с весом $1.0$:

$$\hat{A}^{\text{tot}} = \hat{A}^1_{\text{norm}} + \hat{A}^2_{\text{norm}} + \hat{A}^3_{\text{norm}}$$

**Баланс достигается автоматически** за счет нормализации!

> **Примечание:** Внутри каждого критика (при расчете $r_t^k$) есть весовые коэффициенты для отдельных слагаемых наград (например, $w_{\text{vel}} = 2.0$, $w_{\text{ee\_pos}} = 5.0$). Эти веса являются **гиперпараметрами**, заданными вручную.

### 3.4 Обучение Актора (Actor / Policy)

#### Архитектура

**Actor** $\pi_\theta$ — это **одна нейросеть**.

```
Input: Observation o_t (онбордная информация, без привилегий)
  ↓
Hidden Layers (MLP)
  ↓
Output: Action a_t ~ π_θ(·|o_t)
```

#### PPO Loss (Proximal Policy Optimization)

Функция потерь для актора:

$$\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t \left[ \min \left( r_t(\theta) \hat{A}^{\text{tot}}_t, \; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}^{\text{tot}}_t \right) \right]$$

Где:
- $r_t(\theta) = \frac{\pi_\theta(a_t|o_t)}{\pi_{\theta_{\text{old}}}(a_t|o_t)}$ — отношение вероятностей (ratio)
- $\hat{A}^{\text{tot}}_t$ — **агрегированное преимущество** (из Multi-Critic!)
- $\epsilon = 0.2$ — клиппинг (обычно)

**Градиент:**

$$\nabla_\theta \mathcal{L}^{\text{CLIP}} \propto \hat{A}^{\text{tot}}_t \cdot \nabla_\theta \log \pi_\theta(a_t|o_t)$$

**Интерпретация:**
- Если $\hat{A}^{\text{tot}}_t > 0$ → увеличиваем вероятность действия $a_t$
- Если $\hat{A}^{\text{tot}}_t < 0$ → уменьшаем вероятность действия $a_t$

#### Четыре независимых Loss'а

На каждой итерации обучения оптимизируются **параллельно**:

| Loss | Оптимизирует | Зависит от | Градиент течет через |
|------|-------------|-----------|---------------------|
| $\mathcal{L}^{\text{Actor}}$ | Веса Actor $\theta$ | $\hat{A}^{\text{tot}}$ | Actor Network |
| $\mathcal{L}^{\text{Critic 1}}$ | Веса Critic 1 $\phi_1$ | $r^{\text{loco}}$ | Critic 1 Network |
| $\mathcal{L}^{\text{Critic 2}}$ | Веса Critic 2 $\phi_2$ | $r^{\text{mani}}$ | Critic 2 Network |
| $\mathcal{L}^{\text{Critic 3}}$ | Веса Critic 3 $\phi_3$ | $r^{\text{contact}}$ | Critic 3 Network |

**Критически важно:**
- Градиенты критиков **НЕ течут** в Actor
- Градиент Actor **НЕ течет** в критики
- Критики обучаются **изолированно** друг от друга

#### Псевдокод обучения

```python
for epoch in range(num_epochs):
    # 1. Сбор данных (Rollout)
    states, actions, rewards_dict, next_states = collect_rollout(actor, env)
    
    # 2. Вычисление Advantage для каждого критика
    A_loco = compute_gae(critic_1, states, rewards_dict['loco'], next_states)
    A_mani = compute_gae(critic_2, states, rewards_dict['mani'], next_states)
    A_contact = compute_gae(critic_3, states, rewards_dict['contact'], next_states)
    
    # 3. Нормализация и агрегация
    A_loco_norm = (A_loco - A_loco.mean()) / (A_loco.std() + 1e-8)
    A_mani_norm = (A_mani - A_mani.mean()) / (A_mani.std() + 1e-8)
    A_contact_norm = (A_contact - A_contact.mean()) / (A_contact.std() + 1e-8)
    
    A_total = A_loco_norm + A_mani_norm + A_contact_norm  # Просто сумма!
    
    # 4. Обновление Actor (одним градиентом)
    loss_actor = ppo_clip_loss(actor, states, actions, A_total)
    optimizer_actor.zero_grad()
    loss_actor.backward()
    optimizer_actor.step()
    
    # 5. Обновление Critics (параллельно, независимо)
    for critic, rewards_k in zip([critic_1, critic_2, critic_3], 
                                  [rewards_dict['loco'], rewards_dict['mani'], rewards_dict['contact']]):
        V_pred = critic(states)
        V_target = compute_td_target(rewards_k, critic(next_states))
        loss_critic = mse_loss(V_pred, V_target)
        
        optimizer_critic.zero_grad()
        loss_critic.backward()
        optimizer_critic.step()
```

## 4. Механизм Работы (Data Flow)

### 4.1 Полная Схема

```
┌──────────────────────────────────────────────────────────────────┐
│                    ФАЗА 1: FORWARD PASS                          │
│                    (Сбор данных)                                 │
└──────────────────────────────────────────────────────────────────┘

Состояние s_t (privileged)
    │
    ├────────────────────────────────────────────┐
    │                                            │
    ↓                                            ↓
Observation o_t (onboard)                   s_t, s_{t+1}
    │                                            │
    ↓                                            ↓
┌────────────┐                      ┌────────────────────────────┐
│   ACTOR    │                      │    CRITICS (×3)            │
│   π_θ      │                      │                            │
└────────────┘                      │  Critic 1: φ_loco          │
    │                               │  Critic 2: φ_mani          │
    │ Действие a_t                  │  Critic 3: φ_cs            │
    │                               └────────────────────────────┘
    ↓                                            │
┌────────────┐                                   │
│   СРЕДА    │                                   │
└────────────┘                                   │
    │                                            │
    │ Возвращает:                                │
    │  - s_{t+1}                                 │
    │  - r^loco, r^mani, r^contact               │
    │                                            │
    └────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐
│                    ФАЗА 2: ADVANTAGE COMPUTATION                 │
│                    (Математика, не градиенты)                    │
└──────────────────────────────────────────────────────────────────┘

Critic 1 (φ_loco):
  s_t, s_{t+1}, r^loco  →  V^loco(s_t), V^loco(s_{t+1})
    →  δ^loco = r^loco + γ·V^loco(s_{t+1}) - V^loco(s_t)
    →  GAE  →  Â^loco

Critic 2 (φ_mani):
  s_t, s_{t+1}, r^mani  →  V^mani(s_t), V^mani(s_{t+1})
    →  δ^mani = r^mani + γ·V^mani(s_{t+1}) - V^mani(s_t)
    →  GAE  →  Â^mani

Critic 3 (φ_cs):
  s_t, s_{t+1}, r^contact  →  V^cs(s_t), V^cs(s_{t+1})
    →  δ^contact = r^contact + γ·V^cs(s_{t+1}) - V^cs(s_t)
    →  GAE  →  Â^contact

        ↓ ↓ ↓

┌────────────────────────────────────────────────────────┐
│  НОРМАЛИЗАЦИЯ (приведение к одному масштабу)           │
│                                                        │
│  Â^loco_norm   = (Â^loco - μ) / σ                     │
│  Â^mani_norm   = (Â^mani - μ) / σ                     │
│  Â^contact_norm = (Â^contact - μ) / σ                 │
└────────────────────────────────────────────────────────┘

        ↓

┌────────────────────────────────────────────────────────┐
│  АГРЕГАЦИЯ (простое сложение)                          │
│                                                        │
│  Â^tot = Â^loco_norm + Â^mani_norm + Â^contact_norm   │
│                                                        │

└────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────┐

┌─────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ОБНОВЛЕНИЕ CRITICS (параллельно, независимо)               │
│                                                             │

│       ↓                                                     │
│    ∇_{φ1} Loss_1                                            │
│       ↓                                                     │
│    φ_1 ← φ_1 - α·∇_{φ1} Loss_1                             │
│                                                             │
```

### 4.2 Ключевые Точки Data Flow

#### Точка 1: Смешивание происходит в "цифрах", не в нейронах

- **НЕ смешиваются:** скрытые слои нейросетей критиков
- **Смешиваются:** скалярные значения $\hat{A}^k$ (три числа → одно число)

#### Точка 2: Один градиент для Actor

Actor видит только **один** сигнал $\hat{A}^{\text{tot}}$, который уже является "консенсусом" трех критиков.

Математически это эквивалентно сложению градиентов:

$$\nabla_\theta \mathcal{L}(\theta; \hat{A}^{\text{tot}}) = \nabla_\theta \mathcal{L}(\theta; \hat{A}^1) + \nabla_\theta \mathcal{L}(\theta; \hat{A}^2) + \nabla_\theta \mathcal{L}(\theta; \hat{A}^3)$$

Но концептуально проще: Actor просто видит "общий балл за успеваемость", который сложился из оценок по разным предметам.

#### Точка 3: Изоляция критиков

Критики:
- **Не знают** о существовании друг друга
- **Не обмениваются** информацией
- **Не влияют** друг на друга через градиенты

Каждый критик решает свою задачу регрессии независимо.

## 5. Экспериментальное Подтверждение

### 5.1 Сравнение с Single-Critic (Раздел 7.2.2 статьи)

#### Эксперимент

Авторы обучили две версии робота на задаче одновременной ходьбы и манипуляции:

1. **Single-Critic:** Один критик оценивает $V(s_t)$ для всех наград вместе
2. **Multi-Critic:** Три критика (архитектура из этой работы)

#### Результаты

| Метод | Качество ходьбы | Качество манипуляции | Поведение |
|-------|----------------|---------------------|-----------|
| **Single-Critic** | ❌ **ПРОВАЛ** | ✅ Отлично | Робот **стоит на месте**, игнорируя команды скорости базы, чтобы максимизировать точность руки |
| **Multi-Critic** | ✅ Отлично | ✅ Отлично | Робот идет и **координирует** движения всего тела: база помогает руке расширять рабочее пространство |

#### Интерпретация

**Почему Single-Critic провалился?**

Награда за позицию энд-эффектора имеет большую величину и плотность (получается на каждом шаге). Она "заглушила" награду за ходьбу в процессе обучения.

Робот нашел "хак": если стоять неподвижно, рука дрожит меньше → точность максимальна → награда высокая.

**Почему Multi-Critic справился?**

Благодаря нормализации, сигнал от критика "Locomotion" имеет **равный вес** с сигналом от критика "Manipulation".

Actor вынужден искать компромисс: двигать базу (чтобы удовлетворить Critic 1) **И** держать руку точно (чтобы удовлетворить Critic 2).

### 5.2 Качественный результат

После обучения с Multi-Critic роботом возникает **эмерджентное поведение**:

> Робот активно использует движения базы, чтобы расширить досягаемость руки. Например, если цель впереди, робот делает шаг вперед, одновременно вытягивая руку.

Это **не было явно запрограммировано** — политика самостоятельно выучила координацию всего тела.

## 6. Резюме Ключевых Моментов

### 6.1 Архитектурные принципы

| Принцип | Описание |
|---------|----------|
| **Три независимые нейросети-критика** | Каждая оценивает ценность состояния $V(s_t)$ с своей точки зрения |
| **Вход:** только $s_t$ | Предыдущее состояние и награда НЕ подаются на вход |
| **Выход:** одно число $V(s_t)$ | Предсказанная суммарная награда по специфической задаче |
| **Обучение через TD-Learning** | Используется реальная награда $r_t$ как "якорь реальности" |

### 6.2 Процесс обучения

| Этап | Ключевая идея |
|------|--------------|
| **GAE для каждого критика** | Вычисление $\hat{A}^k$ независимо, с учетом TD-ошибок |
| **Нормализация** | Приведение преимуществ к одному масштабу: $(\hat{A} - \mu) / \sigma$ |
| **Агрегация без весов** | Простое сложение: $\hat{A}^{\text{tot}} = \sum_k \hat{A}^k_{\text{norm}}$ |
| **Один градиент для Actor** | Пропорционален суммарному $\hat{A}^{\text{tot}}$ |
| **Изолированное обучение критиков** | Каждый минимизирует свой MSE Loss независимо |

### 6.3 Преимущества метода

✅ **Автоматический баланс задач:** Достигается через нормализацию, без ручной настройки весов $\alpha_k$

✅ **Меньше гиперпараметров:** Нет нужды подбирать веса агрегации

✅ **Разрешение конфликтов:** Критики "развязаны", не мешают друг другу учиться

✅ **Эмерджентная координация:** Робот самостоятельно выучивает движения всего тела

✅ **Стабильность обучения:** Каждый критик фокусируется на своей задаче, что упрощает оптимизацию

### 6.4 Формулы-шпаргалка

#### Уравнение Беллмана (Target для критика):
$$V_{\text{target}} = r_t + \gamma V_{\phi}(s_{t+1})$$

#### TD-ошибка:
$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

#### GAE (Generalized Advantage Estimation):
$$\hat{A}_t = \sum_{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}$$

#### Нормализация Advantage:
$$\hat{A}^k_{\text{norm}} = \frac{\hat{A}^k - \mu(\hat{A}^k)}{\sigma(\hat{A}^k) + \epsilon}$$

#### Агрегация (Multi-Critic):
$$\hat{A}^{\text{tot}}_t = \sum_{k=1}^{K} \hat{A}^k_{\text{norm}}$$

#### Loss для критика:
$$\mathcal{L}(\phi_k) = \frac{1}{N} \sum_{i=1}^N (V_{\phi_k}(s_i) - V_{\text{target}, i})^2$$

#### PPO Loss для Actor:
$$\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t \left[ \min \left( r_t(\theta) \hat{A}^{\text{tot}}_t, \; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}^{\text{tot}}_t \right) \right]$$

Где $r_t(\theta) = \frac{\pi_\theta(a_t|o_t)}{\pi_{\theta_{\text{old}}}(a_t|o_t)}$
