## 1. Основная Идея и Мотивация

### 1.1 Проблема: Конфликт Задач

В задачах **whole-body control** (управления всем телом) робот должен одновременно решать две конфликтующие задачи:

- **Локомоция (Locomotion):** Стабильная ходьба, поддержание баланса
- **Манипуляция (Manipulation):** Точное управление рукой для достижения цели

**Фундаментальная проблема:**

Награды за локомоцию ($r_{\text{loco}}$) обычно имеют **гораздо большую величину и дисперсию**, чем награды за манипуляцию ($r_{\text{mani}}$).

### 1.2 Что Происходит в Стандартном RL

В классическом подходе используется **один критик** $V(s)$, который оценивает общую награду:

$$r_t = r_{\text{loco}} + r_{\text{manip}}$$

**Проблемы:**

1. **Потеря сигнала:** Сигнал обучения для руки "тонет" в шуме от ходьбы
   - Если $r_{\text{loco}} \sim \pm 100$, а $r_{\text{manip}} \sim \pm 1$
   - Градиенты для руки становятся неразличимыми

2. **Локальный минимум:** Агент "боится" испортить ходьбу
   - Робот научается хорошо ходить
   - Но рука просто "висит плетью" или делает безопасные минимальные движения

3. **Катастрофическое забывание:** Если робот падает
   - Получает огромный отрицательный сигнал $A_{\text{total}} = -100$
   - Наказываются **все** действия, включая правильные движения руки
   - Агент решает "замереть", чтобы не делать хуже

### 1.3 Решение: Advantage Mixing

**Ключевая идея:** Разделить сигналы обучения на основе **причинно-следственной структуры** задачи.

> *"Рука практически не влияет на устойчивость базы (она легкая). Поэтому преимущество, связанное с локомоцией, для руки является просто шумом."*

**Математический подход:**
- Ввести **два критика:** $V_{\text{loco}}$ и $V_{\text{total}}$
- Вычислить **два преимущества:** $A_{\text{loco}}$ и $A_{\text{manip}}$
- Использовать **разные сигналы** для ног и руки при обучении

## 2. Математическая Формулировка

### 2.1 Два Критика (Value Functions)

#### Критик 1: Locomotion Value $V_{\text{loco}}(s)$

**Цель:** Предсказывать **только** награду за локомоцию

$$V_{\text{loco}}(s) = \mathbb{E} \left[ \sum_{t=0}^{\infty} \gamma^t r_{\text{loco}}(s_t) \mid s_0 = s \right]$$

**Обучается на:**
- Награды за скорость базы
- Награды за ориентацию корпуса
- Штрафы за потерю баланса

#### Критик 2: Total Value $V_{\text{total}}(s)$

**Цель:** Предсказывать **полную** награду (локомоция + манипуляция)

$$V_{\text{total}}(s) = \mathbb{E} \left[ \sum_{t=0}^{\infty} \gamma^t (r_{\text{loco}}(s_t) + r_{\text{manip}}(s_t)) \mid s_0 = s \right]$$

**Обучается на:**
- Все награды за локомоцию
- Награды за точность позиции руки
- Награды за ориентацию энд-эффектора

### 2.2 Вычисление Преимуществ (Advantages)

#### Advantage для Локомоции

$$A_{\text{loco}}(s_t, a_t) = r_{\text{loco}}(s_t) + \gamma V_{\text{loco}}(s_{t+1}) - V_{\text{loco}}(s_t)$$

**Интерпретация:** "Насколько действие $a_t$ было хорошо **для ходьбы**?"

#### Advantage для Всей Задачи

$$A_{\text{total}}(s_t, a_t) = r_{\text{total}}(s_t) + \gamma V_{\text{total}}(s_{t+1}) - V_{\text{total}}(s_t)$$

**Интерпретация:** "Насколько действие $a_t$ было хорошо **в целом**?"

#### Advantage для Манипуляции (Ключевой Момент!)

$$A_{\text{manip}}(s_t, a_t) = A_{\text{total}}(s_t, a_t) - A_{\text{loco}}(s_t, a_t)$$

**Интерпретация:** "Насколько действие было хорошо **для руки**, если вычесть влияние ходьбы?"

**Почему это работает?**

Математически, разность $A_{\text{total}} - A_{\text{loco}}$ является **оценкой преимущества только для манипуляции**, полученной робастным способом через **вычитание базовой линии** (baseline subtraction).

### 2.3 Разделение Градиентов (The Core Idea)

#### Градиент для Ног

Ноги влияют на **обе** задачи (они двигают базу, на которой стоит рука):

$$\nabla J_{\text{legs}} \propto A_{\text{total}} \cdot \nabla_\theta \log \pi_{\text{legs}}(a_{\text{legs}}|s)$$

#### Градиент для Руки

Рука влияет **только** на манипуляцию (она легкая и не нарушает баланс):

$$\nabla J_{\text{arm}} \propto (A_{\text{total}} - A_{\text{loco}}) \cdot \nabla_\theta \log \pi_{\text{arm}}(a_{\text{arm}}|s)$$

$$\nabla J_{\text{arm}} \propto A_{\text{manip}} \cdot \nabla_\theta \log \pi_{\text{arm}}(a_{\text{arm}}|s)$$

### 2.4 Что Это Дает?

#### Устранение Интерференции

Рука учится только на том, как её действия улучшили задачу манипуляции, **игнорируя** то, споткнулся робот в этот момент или нет.

#### Выход из Локальных Минимумов

**Пример:**

Робот упал ($A_{\text{loco}} = -100$), но рука приблизилась к цели ($A_{\text{manip}} = +10$).

| Метод | Сигнал для руки | Результат |
|-------|----------------|-----------|
| **Стандартный PPO** | $A_{\text{total}} = -90$ | "Ужасное действие! Не делай так!" ❌ |
| **Advantage Mixing** | $A_{\text{manip}} = +10$ | "Отличное движение! Закрепи!" ✅ |

**Вывод:** Рука получает "чистый" сигнал о задаче, даже если робот при этом упал.

## 3. Архитектура Системы

### 3.1 Unified Policy Network (Единая Нейросеть)

Вместо двух отдельных нейросетей используется **одна сеть с общим "стволом"** и **разными "головами"**.

```
┌──────────────────────────────────────────────────────────────┐
│                      INPUT (Состояние s_t)                    │
│                                                               │
│  • Углы суставов (joint positions)                           │
│  • Скорости суставов (joint velocities)                      │
│  • Ориентация корпуса (base orientation)                     │
│  • История движений (10 последних шагов)                     │
└──────────────────────────────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────┐
│                    SHARED BACKBONE (MLP)                      │
│                    [Общие скрытые слои]                       │
│                                                               │
│  • 3-4 полносвязных слоя                                     │
│  • Извлекает общие признаки: баланс, скорость, наклон        │
│  • Веса общие для всех задач                                 │
└──────────────────────────────────────────────────────────────┘
                              ↓
        ┌─────────────────────┼─────────────────────┐
        ↓                     ↓                     ↓
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│  LEGS HEAD    │     │   ARM HEAD    │     │  CRITIC HEADS │
│  (Policy)     │     │   (Policy)    │     │   (Value)     │
│               │     │               │     │               │
│ Output:       │     │ Output:       │     │ Output:       │
│ μ_legs [12]   │     │ μ_arm [6]     │     │ V_loco  [1]   │
│               │     │               │     │ V_total [1]   │
│ (Средние для  │     │ (Средние для  │     │               │
│  12 моторов   │     │  6 моторов    │     │               │
│  ног)         │     │  руки)        │     │               │
└───────────────┘     └───────────────┘     └───────────────┘
        │                     │                     │
        ↓                     ↓                     ↓
   a_legs [12]           a_arm [6]          Оценки ценности
   + шум                 + шум              (для расчета A)
```

### 3.2 Почему Единая Сеть Лучше Двух Отдельных?

#### Преимущество 1: Проприоцептивное Сопряжение

**Единая сеть:**
- "Мозг" чувствует все тело целиком через общие скрытые слои
- Рука знает в деталях, что делают ноги (и наоборот)

**Две отдельные сети:**
- Каждая часть знает о другой только через внешние сенсоры
- Отсутствие "внутреннего чувства" координации

#### Преимущество 2: Предиктивная Компенсация (Эффект "Лодки")

**Проблема:** Если рука резко дергается, она создает момент силы, который толкает корпус.

**Единая сеть:**
- Предполагает этот толчок (сама его инициировала в соседней голове)
- Может начать компенсировать движение ног **ДО** того, как рука закончила

**Две отдельные сети:**
- Сеть ног воспримет это как "внешний шум" или "толчок"
- Будет только реактивно бороться с ним (запаздывание)

#### Преимущество 3: Общие Признаки

И ходьбе, и манипуляции нужно понимать одно и то же:
- Где находится горизонт
- Какая сейчас скорость
- Не скользко ли

**Единая сеть:** Backbone учит эти "физические концепции" **один раз** для всех

**Две отдельные сети:** Обучаются этому по отдельности (в 2 раза больше данных)

### 3.3 Структура Критиков

**Важно:** Критики — это **не отдельные нейросети**, а две выходные "головы" той же единой сети!

```
Состояние s_t
    ↓
Shared Backbone (извлечение признаков)
    ↓
┌───────────────────────────────────┐
│  Скрытое представление h          │
│  (например, вектор размера 256)   │
└───────────────────────────────────┘
         │                │
         ↓                ↓
    ┌─────────┐      ┌─────────┐
    │ FC [1]  │      │ FC [1]  │
    └─────────┘      └─────────┘
         │                │
         ↓                ↓
    V_loco [1]       V_total [1]
```

**Обучение:**
- Голова $V_{\text{loco}}$ сравнивает свой выход с $R_{\text{loco}}$ (MSE Loss)
- Голова $V_{\text{total}}$ сравнивает свой выход с $R_{\text{total}}$ (MSE Loss)
- Градиенты от обоих лоссов спускаются в Backbone и суммируются

## 4. Forward Pass: От Состояния к Действию

### 4.1 Что Выдает Нейросеть? (Детерминированный Выход)

**Важно:** Нейросеть выдает НЕ сами действия, а **параметры вероятностного распределения**.

Для робота с 18 моторами (12 ног + 6 рука):

#### Выход Policy Head:

$$\mu = [\mu_1, \mu_2, \dots, \mu_{18}] \quad \text{(средние значения)}$$

$$\sigma = [\sigma_1, \sigma_2, \dots, \sigma_{18}] \quad \text{(стандартные отклонения)}$$

Обычно $\sigma$ — это обучаемый параметр, не зависящий от входа.

**Интерпретация:**
- $\mu_i$ — "планируемый" угол для $i$-го мотора
- $\sigma_i$ — "уверенность" робота (маленькая $\sigma$ = уверен, большая $\sigma$ = неуверен)

### 4.2 Sampling: Получение Случайного Действия

Чтобы робот мог **исследовать** мир (exploration), мы добавляем случайный шум:

$$a_i = \mu_i + \epsilon \cdot \sigma_i$$

Где $\epsilon \sim \mathcal{N}(0, 1)$ — случайное число из стандартного нормального распределения.

**Пример:**

```python
# Сеть выдала
mu_arm[0] = 10°     # Среднее для первого мотора руки
sigma_arm[0] = 1°   # Неуверенность

# Случайный шум
epsilon = np.random.randn()  # например, 1.5

# Реальное действие
a_arm[0] = 10° + 1.5 * 1° = 11.5°
```

Именно **11.5°** отправляется на мотор робота.

### 4.3 Вычисление Log Prob (Оценка Вероятности)

Сразу после получения действия $a$ мы запоминаем: **"Насколько это действие было вероятным?"**

$$\log \pi(a|s) = \sum_{i=1}^{18} \log \mathcal{N}(a_i | \mu_i, \sigma_i)$$

Для нормального распределения:

$$\log \mathcal{N}(a_i | \mu_i, \sigma_i) = -\frac{(a_i - \mu_i)^2}{2\sigma_i^2} - \log(\sigma_i) - \frac{1}{2}\log(2\pi)$$

**Интерпретация:**
- Если $a_i$ близко к $\mu_i$ → $\log \pi$ высокий (действие ожидаемое)
- Если $a_i$ далеко от $\mu_i$ → $\log \pi$ низкий (действие неожиданное)

### 4.4 Зачем Нужен Log Prob?

**Log Prob — это "точка опоры" для градиента.**

Градиент функции $\nabla_\theta \log \pi(a|s)$ показывает:

> *"В какую сторону мне нужно сдвинуть параметры сети ($\mu$ и $\sigma$), чтобы действие $a$ стало выпадать чаще?"*

В Advantage Mixing мы вычисляем **два отдельных Log Prob**:

$$\log \pi_{\text{legs}}(a_{\text{legs}}|s) = \sum_{i=1}^{12} \log \mathcal{N}(a_i | \mu_i, \sigma_i)$$

$$\log \pi_{\text{arm}}(a_{\text{arm}}|s) = \sum_{i=13}^{18} \log \mathcal{N}(a_i | \mu_i, \sigma_i)$$

**Зачем раздельно?**

Чтобы успех руки не "размывался" на фоне уверенного (но возможно ошибочного) движения ног.

### 4.5 Итоги Forward Pass

После одного шага мы имеем:

| Переменная | Размерность | Описание |
|------------|------------|----------|
| $a_{\text{legs}}$ | [12] | Действия для ног (на моторы) |
| $a_{\text{arm}}$ | [6] | Действия для руки (на моторы) |
| $\log \pi_{\text{legs}}$ | [1] | Вероятность действий ног |
| $\log \pi_{\text{arm}}$ | [1] | Вероятность действий руки |
| $V_{\text{loco}}$ | [1] | Оценка ценности (локомоция) |
| $V_{\text{total}}$ | [1] | Оценка ценности (всё) |

Всё это **сохраняется в буфер** для последующего обучения.

## 5. Backward Pass: Обучение через Градиенты

### 5.1 Расчет Advantage (После Сбора Данных)

Когда буфер заполнен (например, 20 000 шагов), мы вычисляем **для каждого шага**:

#### Advantage для Локомоции

$$A_{\text{loco}}^{(t)} = r_{\text{loco}}^{(t)} + \gamma V_{\text{loco}}(s_{t+1}) - V_{\text{loco}}(s_t)$$

Или через GAE (Generalized Advantage Estimation):

$$A_{\text{loco}}^{(t)} = \sum_{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}^{\text{loco}}$$

Где $\delta_t^{\text{loco}} = r_{\text{loco}}^{(t)} + \gamma V_{\text{loco}}(s_{t+1}) - V_{\text{loco}}(s_t)$

#### Advantage для Всей Задачи

$$A_{\text{total}}^{(t)} = r_{\text{total}}^{(t)} + \gamma V_{\text{total}}(s_{t+1}) - V_{\text{total}}(s_t)$$

#### Advantage для Манипуляции

$$A_{\text{manip}}^{(t)} = A_{\text{total}}^{(t)} - A_{\text{loco}}^{(t)}$$

**Почему это работает?**

$$A_{\text{manip}} = (r_{\text{loco}} + r_{\text{manip}} + \gamma V_{\text{total}}(s_{t+1}) - V_{\text{total}}(s_t)) - (r_{\text{loco}} + \gamma V_{\text{loco}}(s_{t+1}) - V_{\text{loco}}(s_t))$$

Упрощая:

$$A_{\text{manip}} \approx r_{\text{manip}} + \gamma [V_{\text{total}}(s_{t+1}) - V_{\text{loco}}(s_{t+1})] - [V_{\text{total}}(s_t) - V_{\text{loco}}(s_t)]$$

Это "чистый" сигнал манипуляции, из которого вычтен "шум" локомоции.

### 5.2 Advantage Mixing: Формирование Целей

Вводится параметр **curriculum** $\beta \in [0, 1]$, который растет от 0 до 1 по мере обучения.

#### Цель для Ног (Target for Legs)

$$T_{\text{legs}} = A_{\text{loco}} + \beta \cdot A_{\text{manip}}$$

**Интерпретация при разных $\beta$:**
- $\beta = 0$: Ноги учатся **только** на локомоции
- $\beta = 1$: Ноги учатся на **полном** преимуществе

#### Цель для Руки (Target for Arm)

$$T_{\text{arm}} = A_{\text{manip}} + \beta \cdot A_{\text{loco}}$$

**Интерпретация при разных $\beta$:**
- $\beta = 0$: Рука учится **только** на манипуляции
- $\beta = 1$: Рука учится на **полном** преимуществе

### 5.3 PPO Loss с Advantage Mixing

#### Стандартный PPO Loss (для справки)

$$L^{\text{PPO}}(\theta) = \mathbb{E} \left[ \min \left( r_t(\theta) A_t, \; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t \right) \right]$$

Где:

$$r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\text{old}}}(a_t|s_t)}$$

#### Advantage Mixing Loss

$$L^{\text{Actor}}(\theta) = L^{\text{legs}}(\theta) + L^{\text{arm}}(\theta)$$

Где:

$$L^{\text{legs}}(\theta) = \mathbb{E} \left[ \min \left( r_t^{\text{legs}}(\theta) T_{\text{legs}}, \; \text{clip}(r_t^{\text{legs}}(\theta), 1-\epsilon, 1+\epsilon) T_{\text{legs}} \right) \right]$$

$$L^{\text{arm}}(\theta) = \mathbb{E} \left[ \min \left( r_t^{\text{arm}}(\theta) T_{\text{arm}}, \; \text{clip}(r_t^{\text{arm}}(\theta), 1-\epsilon, 1+\epsilon) T_{\text{arm}} \right) \right]$$

И:

$$r_t^{\text{legs}}(\theta) = \frac{\pi_\theta(a_{\text{legs}}|s_t)}{\pi_{\theta_{\text{old}}}(a_{\text{legs}}|s_t)}$$

$$r_t^{\text{arm}}(\theta) = \frac{\pi_\theta(a_{\text{arm}}|s_t)}{\pi_{\theta_{\text{old}}}(a_{\text{arm}}|s_t)}$$

### 5.4 Как Текут Градиенты

#### На Уровне Голов (Разделение)

```
Loss_arm → clip(ratio_arm * T_arm)
    ↓
∇_θ log π_arm
    ↓
Градиент течет только в ARM HEAD (6 выходов)
```

```
Loss_legs → clip(ratio_legs * T_legs)
    ↓
∇_θ log π_legs
    ↓
Градиент течет только в LEGS HEAD (12 выходов)
```

#### На Уровне Backbone (Слияние)

В точке соединения голов с общим телом градиенты **складываются**:

$$\nabla_{\theta_{\text{backbone}}} L^{\text{Total}} = \nabla_{\theta_{\text{backbone}}} L^{\text{legs}} + \nabla_{\theta_{\text{backbone}}} L^{\text{arm}}$$

**Результат:**

Общие слои учатся извлекать признаки, которые удовлетворяют **обе** задачи одновременно, но с учетом их разной важности (через $T_{\text{legs}}$ и $T_{\text{arm}}$).

### 5.5 Обучение Критиков

Параллельно обучаются критики через стандартный MSE Loss:

$$L^{\text{Critic}_{\text{loco}}} = \frac{1}{N} \sum_{i=1}^{N} (V_{\text{loco}}(s_i) - R_{\text{loco}, i})^2$$

$$L^{\text{Critic}_{\text{total}}} = \frac{1}{N} \sum_{i=1}^{N} (V_{\text{total}}(s_i) - R_{\text{total}, i})^2$$

Где $R$ — это "ground truth" (накопленная награда с дисконтированием).

## 6. Полный Пайплайн Обучения

### 6.1 Цикл Обучения (Outer Loop)

```
┌─────────────────────────────────────────────────────────────┐
│                    ЦИКЛ ОБУЧЕНИЯ (Итерация)                  │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  ШАГ 1: СБОР ДАННЫХ (Exploration)                           │
│  Длительность: 20,000 шагов (или N эпизодов)                │
│  Веса нейросети: ЗАМОРОЖЕНЫ                                  │
└─────────────────────────────────────────────────────────────┘
    │
    │  Для каждого шага t:
    │    1. s_t → Сеть → μ, σ
    │    2. a_t = μ + ε·σ (sampling)
    │    3. Робот выполняет a_t
    │    4. Среда → s_{t+1}, r_loco, r_manip
    │    5. Сохранить в буфер:
    │       (s_t, a_t, r_loco, r_manip, log_prob_old, V_loco, V_total)
    ↓
┌─────────────────────────────────────────────────────────────┐
│  ШАГ 2: РАСЧЕТ ADVANTAGE (Post-processing)                  │
└─────────────────────────────────────────────────────────────┘
    │
    │  Для каждой записи в буфере:
    │    1. A_loco = GAE(r_loco, V_loco)
    │    2. A_total = GAE(r_total, V_total)
    │    3. A_manip = A_total - A_loco
    │
    │    4. T_legs = A_loco + β·A_manip
    │    5. T_arm = A_manip + β·A_loco
    ↓
┌─────────────────────────────────────────────────────────────┐
│  ШАГ 3: ОБУЧЕНИЕ (Mini-batch SGD)                           │
│  Эпохи: 5-10                                                 │
│  Веса нейросети: ОБНОВЛЯЮТСЯ                                 │
└─────────────────────────────────────────────────────────────┘
    │
    │  Для каждой эпохи:
    │    Разделить буфер на mini-batches (например, 256 шагов)
    │
    │    Для каждого mini-batch:
    │      1. Forward Pass:
    │         s → Сеть → μ_new, V_loco_new, V_total_new
    │         log_prob_new = log π(a | μ_new, σ)
    │
    │      2. Compute Losses:
    │         Loss_actor = PPO_clip(log_prob_new, log_prob_old, T_legs, T_arm)
    │         Loss_critic_loco = MSE(V_loco_new, R_loco)
    │         Loss_critic_total = MSE(V_total_new, R_total)
    │
    │      3. Backward:
    │         Loss_total = Loss_actor + Loss_critic_loco + Loss_critic_total
    │         Loss_total.backward()
    │         optimizer.step()
    ↓
┌─────────────────────────────────────────────────────────────┐
│  ШАГ 4: ОЧИСТКА БУФЕРА                                       │
│  Буфер полностью удаляется (On-Policy)                       │
└─────────────────────────────────────────────────────────────┘
    │
    │  Увеличить β (если нужно)
    │  β ← β + Δβ (линейный рост от 0 до 1)
    ↓
┌─────────────────────────────────────────────────────────────┐
│  ПОВТОРИТЬ ЦИКЛ                                              │
│  (с обновленными весами)                                     │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 Почему Буфер Нужно Удалять? (On-Policy)

PPO — это **on-policy** алгоритм. Это значит, что данные валидны только для текущей версии политики.

**Проблема с сохранением старых данных:**

Если данные были собраны "глупой" версией сети (100 итераций назад):

$$r_t(\theta) = \frac{\pi_{\text{new}}(a|s)}{\pi_{\text{old}}(a|s)} \to \infty$$

Математика PPO сломается, потому что отношение станет огромным.

**Решение:** Собрали → выжали максимум → выкинули → пошли собирать заново.

### 6.3 Роль Curriculum ($\beta$)

$\beta$ растет линейно от 0 до 1 за время обучения:

$$\beta(t) = \min\left(1, \frac{t}{T_{\text{curriculum}}}\right)$$

**Зачем это нужно?**

| Этап | $\beta$ | Что происходит |
|------|---------|----------------|
| **Начало обучения** | $\beta \approx 0$ | Рука и ноги учатся **независимо**, не мешая друг другу |
| **Середина** | $\beta \approx 0.5$ | Начинается координация (ноги начинают "чувствовать" успех руки) |
| **Конец** | $\beta = 1$ | Полная интеграция (как обычный PPO, но с выученными базовыми навыками) |

**Пример:**

При $\beta = 0$:
- Рука учится: "Дотянуться до кружки"
- Ноги учатся: "Не упасть"

При $\beta = 1$:
- Рука учится: "Дотянуться, но не слишком резко (чтобы не опрокинуть робота)"
- Ноги учатся: "Подшагнуть вперед, чтобы помочь руке дотянуться дальше"

## 7. Формулы с Бета: Детальный Разбор

### 7.1 Общая Формула Градиента

Итоговый градиент политики представляет собой сумму:

$$\nabla J(\theta) = \nabla J_{\text{arm}}(\theta) + \nabla J_{\text{legs}}(\theta)$$

Где:

$$\nabla J_{\text{arm}}(\theta) = \mathbb{E} \left[ g_{\text{arm}} \cdot (A_{\text{manip}} + \beta A_{\text{loco}}) \right]$$

$$\nabla J_{\text{legs}}(\theta) = \mathbb{E} \left[ g_{\text{legs}} \cdot (A_{\text{loco}} + \beta A_{\text{manip}}) \right]$$

Здесь:
- $g_{\text{arm}} = \nabla_\theta \log \pi(a_{\text{arm}}|s)$ — вектор градиента для руки
- $g_{\text{legs}} = \nabla_\theta \log \pi(a_{\text{legs}}|s)$ — вектор градиента для ног

### 7.2 Случай A: Начало Обучения ($\beta = 0$)

При $\beta = 0$ формулы упрощаются:

$$\nabla J_{\text{arm}} = \mathbb{E} \left[ g_{\text{arm}} \cdot A_{\text{manip}} \right]$$

$$\nabla J_{\text{legs}} = \mathbb{E} \left[ g_{\text{legs}} \cdot A_{\text{loco}} \right]$$

**Пример:**

Робот упал ($A_{\text{loco}} = -100$), но рука схватила кубок ($A_{\text{manip}} = +10$).

| Часть тела | Градиент | Знак | Что происходит |
|-----------|----------|------|----------------|
| **Рука** | $g_{\text{arm}} \cdot (+10)$ | ➕ | Увеличивает $\pi(a_{\text{arm}})$ — хвалим! |
| **Ноги** | $g_{\text{legs}} \cdot (-100)$ | ➖ | Уменьшает $\pi(a_{\text{legs}})$ — ругаем! |

**Вывод:** Рука и ноги обучаются **независимо**. Провал ног не влияет на обучение руки.

### 7.3 Случай B: Конец Обучения ($\beta = 1$)

При $\beta = 1$ формулы становятся:

$$\nabla J_{\text{arm}} = \mathbb{E} \left[ g_{\text{arm}} \cdot (A_{\text{manip}} + A_{\text{loco}}) \right]$$

$$\nabla J_{\text{legs}} = \mathbb{E} \left[ g_{\text{legs}} \cdot (A_{\text{loco}} + A_{\text{manip}}) \right]$$

Поскольку $A_{\text{total}} = A_{\text{loco}} + A_{\text{manip}}$:

$$\nabla J = \mathbb{E} \left[ (g_{\text{arm}} + g_{\text{legs}}) \cdot A_{\text{total}} \right]$$

Это **точно соответствует стандартному PPO** для единой политики!

**Интерпретация:**

На этом этапе робот уже умеет:
- ✅ Ходить стабильно
- ✅ Двигать рукой точно

Теперь он учится **тонкой координации**:
- Ноги подшагивают, чтобы помочь руке дотянуться дальше
- Рука двигается плавнее, чтобы не опрокинуть робота

### 7.4 Математическая Интуиция: Зачем Вычитание?

Вычитание $A_{\text{total}} - A_{\text{loco}}$ работает как **Conditional Baseline** — метод уменьшения дисперсии в статистике.

#### Без Вычитания (Стандартный PPO)

Gradient variance:

$$\text{Var}[\nabla J_{\text{arm}}] = \text{Var}[g_{\text{arm}} \cdot A_{\text{total}}]$$

Здесь дисперсия **высокая**, потому что $A_{\text{total}}$ содержит шум от локомоции (робот идет по неровной поверхности, постоянно теряет/восстанавливает баланс).

#### С Вычитанием (Advantage Mixing)

Gradient variance:

$$\text{Var}[\nabla J_{\text{arm}}] = \text{Var}[g_{\text{arm}} \cdot (A_{\text{total}} - A_{\text{loco}})]$$

Поскольку $A_{\text{loco}}$ коррелирует с шумом локомоции в $A_{\text{total}}$, их разность имеет **меньшую дисперсию**.

**Математически:**

$$\text{Var}[X - Y] = \text{Var}[X] + \text{Var}[Y] - 2\text{Cov}[X, Y]$$

Если $\text{Cov}[A_{\text{total}}, A_{\text{loco}}]$ высокая (а она высокая!), то дисперсия разности **значительно меньше**.

### 7.5 Реализация в Коде (PyTorch)

```python
# После сбора данных и расчета Advantage
A_loco = compute_gae(rewards_loco, values_loco)
A_total = compute_gae(rewards_total, values_total)
A_manip = A_total - A_loco

# Curriculum parameter
beta = min(1.0, current_iteration / curriculum_iterations)

# Advantage Mixing Targets
target_arm = A_manip + beta * A_loco
target_leg = A_loco + beta * A_manip

# PPO Loss для Actor
ratio_arm = torch.exp(log_prob_arm_new - log_prob_arm_old)
ratio_leg = torch.exp(log_prob_leg_new - log_prob_leg_old)

clip_arm = torch.clamp(ratio_arm, 1 - epsilon, 1 + epsilon)
clip_leg = torch.clamp(ratio_leg, 1 - epsilon, 1 + epsilon)

loss_arm = -torch.min(ratio_arm * target_arm, clip_arm * target_arm).mean()
loss_leg = -torch.min(ratio_leg * target_leg, clip_leg * target_leg).mean()

loss_actor = loss_arm + loss_leg

# Обратное распространение
loss_actor.backward()
optimizer.step()
```

**Критически важно:**

`.detach()` для `target_arm` и `target_leg`, чтобы не дифференцировать сами Advantage (они от критиков).

## 8. Сравнение с Multi-Critic Learning

Оба метода решают проблему конфликтующих задач, но делают это **по-разному**.

### 8.1 Таблица Сравнения

| Аспект | **Multi-Critic Learning** | **Advantage Mixing** |
|--------|---------------------------|----------------------|
| **Количество критиков** | 3 (Loco, Mani, Contact) | 2 (Loco, Total) |
| **Где происходит агрегация** | На уровне **Advantage** (после GAE) | На уровне **градиента** (в формуле PPO) |
| **Используются ли веса $\alpha_k$** | ❌ Нет (только нормализация) | ✅ Да ($\beta$ — curriculum вес) |
| **Архитектура политики** | Одна сеть, одна голова Actor | Одна сеть, **две головы** Actor (Arm + Legs) |
| **Тип разделения** | По **награды** (три группы) | По **частям тела** (рука vs ноги) |
| **Цель** | Баланс через нормализацию масштабов | Чистота сигнала через вычитание базовой линии |
| **Curriculum** | ❌ Нет (баланс с первого шага) | ✅ Да ($\beta: 0 \to 1$) |

### 8.2 Концептуальные Различия

#### Multi-Critic Learning

**Философия:** "Разные эксперты оценивают разные аспекты **одного действия**"

```
Действие a_t
    ↓
┌────────────────────────────────────────┐
│  Критик 1: "Хорошо для ходьбы?"        │
│  Критик 2: "Хорошо для руки?"          │
│  Критик 3: "Хорошо для ритма шагов?"   │
└────────────────────────────────────────┘
    ↓
Нормализация + Суммирование
    ↓
Один общий сигнал A_total
    ↓
Весь Actor обновляется одним градиентом
```

**Преимущество:** Автоматический баланс через нормализацию (меньше гиперпараметров)

#### Advantage Mixing

**Философия:** "Разные части тела учатся на **разных сигналах**"

```
Действие a_t = [a_legs, a_arm]
    ↓
┌────────────────────────────────────────┐
│  Критик 1: V_loco (только локомоция)   │
│  Критик 2: V_total (всё вместе)        │
└────────────────────────────────────────┘
    ↓
A_loco, A_manip = A_total - A_loco
    ↓
┌──────────────────┬──────────────────┐
│  Голова Ног      │  Голова Руки     │
│  Сигнал:         │  Сигнал:         │
│  A_loco + β·A_m  │  A_manip + β·A_l │
└──────────────────┴──────────────────┘
    ↓
Два раздельных градиента → Слияние в Backbone
```

**Преимущество:** Явное разделение по причинно-следственной структуре (рука легкая, не влияет на баланс)

### 8.3 Когда Что Использовать?

| Задача | Рекомендация |
|--------|-------------|
| **Много мелких подзадач** с разными масштабами наград | Multi-Critic (автоматическая нормализация) |
| **Две явно разделимые части тела** (база + манипулятор) | Advantage Mixing (причинно-следственное разделение) |
| **Нужна стабильность с первого шага** | Multi-Critic ($\beta$ не требуется) |
| **Нужно сначала научить базовым навыкам** | Advantage Mixing (curriculum через $\beta$) |
| **Квадруп с тяжелым манипулятором** | Multi-Critic (рука влияет на баланс) |
| **Гуманоид с легкой рукой** | Advantage Mixing (рука не влияет на баланс) |

### 8.4 Могут Ли Они Комбинироваться?

**Да!** Теоретически можно представить гибридную архитектуру:

1. **Три критика** (как в Multi-Critic): Loco, Mani, Contact
2. **Вычислить три Advantage** с нормализацией
3. **Разделить по частям тела** (как в Advantage Mixing):
   - Для ног: $(A_{\text{loco}} + A_{\text{contact}}) + \beta A_{\text{mani}}$
   - Для руки: $A_{\text{mani}} + \beta (A_{\text{loco}} + A_{\text{contact}})$

Это дало бы **и** автоматический баланс масштабов, **и** причинно-следственное разделение.

## 9. Резюме Ключевых Моментов

### 9.1 Основные Принципы

| Принцип | Описание |
|---------|----------|
| **Два критика** | $V_{\text{loco}}$ и $V_{\text{total}}$ оценивают разные награды |
| **Вычитание базовой линии** | $A_{\text{manip}} = A_{\text{total}} - A_{\text{loco}}$ убирает шум |
| **Раздельные головы Actor** | Legs Head (12 выходов) + Arm Head (6 выходов) |
| **Единый Backbone** | Общие скрытые слои для координации |
| **Curriculum через $\beta$** | Плавный переход от независимого к совместному обучению |
| **On-Policy буфер** | Данные собираются и удаляются после каждой итерации |

### 9.2 Формулы-Шпаргалка

#### Advantage для Локомоции:
$$A_{\text{loco}}(s_t, a_t) = r_{\text{loco}}(s_t) + \gamma V_{\text{loco}}(s_{t+1}) - V_{\text{loco}}(s_t)$$

#### Advantage для Манипуляции:
$$A_{\text{manip}}(s_t, a_t) = A_{\text{total}}(s_t, a_t) - A_{\text{loco}}(s_t, a_t)$$

#### Advantage Mixing Targets:
$$T_{\text{legs}} = A_{\text{loco}} + \beta \cdot A_{\text{manip}}$$
$$T_{\text{arm}} = A_{\text{manip}} + \beta \cdot A_{\text{loco}}$$

#### Gradient для Руки:
$$\nabla J_{\text{arm}} = \mathbb{E} \left[ \nabla_\theta \log \pi(a_{\text{arm}}|s) \cdot (A_{\text{manip}} + \beta A_{\text{loco}}) \right]$$

#### Gradient для Ног:
$$\nabla J_{\text{legs}} = \mathbb{E} \left[ \nabla_\theta \log \pi(a_{\text{legs}}|s) \cdot (A_{\text{loco}} + \beta A_{\text{manip}}) \right]$$

#### При $\beta = 1$ (эквивалентно стандартному PPO):
$$\nabla J = \mathbb{E} \left[ (g_{\text{arm}} + g_{\text{legs}}) \cdot A_{\text{total}} \right]$$

### 9.3 Преимущества Метода

✅ **Снижение дисперсии градиента** через вычитание коррелированного шума

✅ **Выход из локальных минимумов** (рука не замирает из-за страха упасть)

✅ **Целостное управление** через единую сеть (координация всего тела)

✅ **Явное причинно-следственное разделение** (рука легкая → не влияет на баланс)

✅ **Curriculum learning** через $\beta$ (сначала базовые навыки, потом координация)

✅ **Эмерджентное поведение** (ноги подшагивают, чтобы помочь руке)

### 9.4 Практические Советы

| Параметр | Рекомендация |
|----------|-------------|
| **$\beta$ расписание** | Линейный рост от 0 до 1 за первые 50% обучения |
| **Размер буфера** | 20,000 - 50,000 шагов (зависит от сложности) |
| **Эпох обучения** | 5-10 (больше = overfitting на старых данных) |
| **Learning rate** | Actor: 3e-4, Critic: 1e-3 |
| **GAE $\lambda$** | 0.95 (стандартное значение) |
| **PPO clip $\epsilon$** | 0.2 (стандартное значение) |

### 9.5 Дополнительные Компоненты (из статьи)

Помимо Advantage Mixing, в статье есть:

1. **Regularized Online Adaptation**
   - Модуль адаптации угадывает скрытые параметры среды (трение, массу груза)
   - Помогает sim-to-real transfer

2. **Privileged Training**
   - Во время обучения критики видят "привилегированную" информацию (карту высот)
   - На реальном роботе её нет, но политика уже обучена с её помощью

3. **History Encoding**
   - Вход сети включает историю за 10 шагов
   - Помогает понимать динамику (ускорение, тренды)
